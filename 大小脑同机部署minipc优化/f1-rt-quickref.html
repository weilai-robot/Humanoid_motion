前提 · preflight + RT 内核

preflight()die分层预检，不是"不符都 warn"

die 硬阻断非 root · 非 x86_64 · 检测到 VM（生产硬实时在 VM 无意义，直接退，不给"勉强继续"选项）· Ubuntu 非 22.04

die 三重校验型号 i7-12800H（model name）· nproc=20 · 14 物理核（lscpu -p=CORE 去重）——任一不符即中止，因 isolcpus=4,5,6,7 按该拓扑写死（原"Ubuntu 非 22.04 / nproc≠20 只 warn"已改为 die）

自动补齐缺 python3/ethtool 则 apt install

对照 realtime-config.sh：它对 VM 是 warn + ask_yn 交互询问；本脚本更严，直接 die。

step_ubuntu_pro_rt必须RT 内核：检测+安装（三阶段）

① 已运行则跳过已是 RT 内核（uname -v/-r 含 RT）→ 跳过安装。但 detach 不卸载内核包，故仍查订阅：未 attached 则 warn 提醒（场景2：内核在跑、实时控制正常，仅失去官方更新补丁，提供 token 重跑即重新 attach）。

② Pro attach已 attached 则跳过；否则读 /etc/f1/pro_token（0600 root:root），文件缺失/为空则交互输入并回写（仅交互输入的 token 回写，从文件读的不重复写）。不依赖 UBUNTU_PRO_TOKEN 环境变量，可安全推 GitHub。

③ enablerealtime-kernel 未 enabled 则 pro enable realtime-kernel --assume-yes 直接装（不再 ask_yn）。

为什么所有后续配置（GRUB/sysctl/systemd）都必须在 RT 内核上才真正生效。原版"未装只 warn"会让人误以为配置完成，实则内核未就绪。

装不上不 dieattach/enable 失败只 warn + return 0——GRUB 等对 RT 内核同样需要，先写无害，用户后续手动装+重启即可。

内核层 · GRUB 命令行（12 项，drop-in 写入）

isolcpus=4,5,6,7必须把 4 个实时核从调度器摘出

是什么内核启动时把这组 CPU 移出默认调度域，普通进程（ROS2/DDS/日志）永远调不到，只有显式绑核的线程能上。

原理4/5 是同一物理核的两个超线程，共享 L1/L2、执行单元、store buffer；只隔离 4 不隔离 5，普通线程仍抢共享资源、驱逐热数据 → 周期性尖峰。

不这么后台线程调度上实时核，1kHz 尾部延迟不可控。

nohz_full=4,5,6,7必须关隔离核周期性 tick

是什么Linux 默认每 CPU 每秒 HZ 次（22.04 约 250）"调度 tick"做时间统计/检查切换。nohz_full 让"只剩一个线程"的核进 full dynticks 模式，关掉这个周期 tick。

原理即使 isolcpus 不让普通线程上核，内核仍按时给实时核发 tick。一次 tick 本身开销 + 调度决策，对 1ms（1000μs）周期是数十 μs 抖动。

前提需配合 rcu_nocbs，且隔离核上只剩目标线程。

rcu_nocbs=4,5,6,7必须RCU 回调迁管家核

是什么RCU（Read-Copy-Update）是内核免锁同步，读端极快，但"延迟回收旧数据"的回调默认在提交它的 CPU 上执行。rcu_nocbs 让隔离核的 RCU 回调转到管家核执行。

为什么回调不频繁，但一旦命中实时循环关键时刻就是不可预测 μs 级抖动。

排除rcu_nocb_poll——它让管家核开轮询线程主动拉取，常驻干扰大脑（导航）CFS 调度，故不加。

irqaffinity=0-3,8-19必须·新增开机最早期中断默认落脚核

是什么内核命令行参数，引导阶段就设"默认中断亲和性"——新设备中断注册（USB 网卡/NVMe 开机枚举）时按掩码决定落哪个 CPU。

为什么必须早它在 init / 任何 systemd 服务之前生效。运行时 set_rt_env.sh 的 default_smp_affinity 是 systemd 阶段才写，晚于开机设备枚举。两者形成"早期兜底（GRUB）+ 精确兜底（运行时动态计算）"两层。

不这么开机早期注册的中断默认落 4-7 污染隔离核，等运行时改已晚（部分中断已服务过）。

intel_pstate=disable必须禁动态调频，改 acpi-cpufreq

是什么intel_pstate 是 Intel 硬件 P-state 驱动，频率随负载变。禁后改 acpi-cpufreq + performance governor 固定最高频。

为什么动态调频 → 同一周期执行时间不稳 → 直接体现为周期抖动。固定最高频后每周期一致。

副作用功耗/发热升（F1 有主动散热，可接受）。

processor/intel_idle.max_cstate=0必须禁 CPU 深度睡眠

是什么CPU 空闲逐级进 C0→C1→C2… 越深越省电但唤醒延迟越大越不可预测。=0 只允许 C0（活跃），不进任何睡眠。

原理实时线程 1ms 间隔若让 CPU 浅睡再唤醒，唤醒延迟（数十 μs）叠加到周期。用功耗换可预测延迟。

注意因 pstate 禁 + performance 已拉满，CPU 大部分时间本在 C0，此项主要堵空闲瞬间的深度睡眠。

watchdog_thresh=60必须调低 NMI 看门狗频率

是什么NMI（不可屏蔽中断）watchdog 是内核检测 CPU 卡死/死锁的机制，定期发不可屏蔽中断检查响应。默认 10 秒一次，watchdog_thresh=60 拉到 60 秒一次（NMI 从每秒一次降到每分钟一次）。

为什么默认 NMI 每秒一次是周期性干扰源。完全关掉会丢失 CPU 卡死时的 backtrace 诊断能力。拉长到 60 秒既把干扰降到几乎为零，又保留卡死现场记录——执行器安全系统需要事后可查。

audit=0必须关 audit 安全审计

是什么Linux audit 记录系统调用/文件访问等安全事件，默认开启维护审计缓冲区、产生后台工作。

为什么F1 封闭控制场景不需审计；后台工作是额外噪声，关掉。

tsc=reliable + clocksource=tsc必须固定时钟源为 TSC

是什么内核时钟源可选 TSC/HPET/ACPI_PM。tsc 是 CPU 内计数器，读取最快（一条指令，纳秒级）；HPET 是主板外置定时器，跨总线慢。clocksource=tsc 强制用 TSC，tsc=reliable 告诉内核"TSC 稳定可信，不用校验切换"。

为什么时钟源切换/校验瞬间有计时跳变。固定后基准稳定，cyclictest 等延迟测量也基于它。

前提i7-12800H 的 TSC 在 C-state 下保持同步（现代 Intel 默认如此），reliable 安全。

transparent_hugepage=never必须禁透明大页 THP

是什么THP 是内核把 4KB 小页自动合并成 2MB 大页的机制，减页表项、提升 TLB 命中。但合并/拆分是异步后台动作。

为什么合并/拆分瞬间页表抖动、TLB 刷新，对实时线程 μs 级噪声。禁后内存页固定可预测。

双保险与 §启动层 THP 禁用服务两层——GRUB 层 + 服务层，任一生效即可。

OS 层 · sysctl / swap / irqbalance / THP

sched_rt_runtime_us=-1建议解除 RT 调度 95% 节流

是什么内核默认给 SCHED_FIFO/RR 设"95% 时间上限"——RT 任务连续占用超配额则强制降级 5% 防锁死系统（安全网）。

为什么隔离核上就是要让 EtherCAT/Control 100% 占用、绝不让出。=-1 关闭节流。

不设实时线程偶尔被强制让出 5%，尾部不可预测抖动。

timer_migration=0建议禁止定时器跨核迁移

是什么内核定时器到期回调默认可跨 CPU 迁移执行。=0 禁止，在哪个核到期就在哪执行。

为什么跨核迁移触发出入队列、缓存污染。不让外部定时器迁进隔离核，也不让管家核定时器迁到实时核。

numa_balancing=0建议关自动 NUMA 均衡

是什么多 NUMA 机器上内核自动把内存迁到离 CPU 近的节点。F1 单 NUMA（i7-12800H 单封装），无收益。

为什么单 NUMA 关掉，避免后台扫描页表、产生不必要唤醒和迁移。

vm.stat_interval=10建议拉长 vmstat 统计间隔

是什么vmstat 后台周期性统计内存状态，默认每秒多次。=10 拉到 10 秒。

为什么统计唤醒 CPU、扫页表。拉长间隔减唤醒频率，降后台噪声。

rtprio / memlock已取消无需为非 root 用户配 limits

已取消控制服务以 root（sudo）运行，pthread_setschedparam/mlockall 在 root 下不受 PAM rtprio/memlock 限制约束；PAM limits 只在用户登录会话生效，systemd 服务以 root 启动不经过 pam_limits。故不再写 f1-realtime.conf，也不建 f1rt 组。

真正前提代码层 pthread_setschedparam 返回值检查（!= 0）才是实时调度生效的关键（见代码层 C1/C2），权限配错会被 <0 bug 吞掉 → 假实时。

swapoff + 注释 fstab必须关闭 swap

是什么swap 是内核把"不活跃"内存页写到磁盘（swap 分区/文件）腾物理内存，需要时读回（换入）。

原理实时线程页若换出，访问触发缺页中断，内核从磁盘读回，I/O 延迟 ms 级远超 1ms。即便内存够用，swap 开着极端情况仍可能换出。

为什么关两次swapoff -a 运行时关，但重启后 fstab 挂 swap 会重启用；注释 fstab 行永久关。两层才彻底。

disable + mask irqbalance建议停用并 mask 中断均衡守护

是什么irqbalance 是系统守护进程，默认每 10s 统计各 CPU 中断负载并自动重分配中断（均衡/省电）。

为什么冲突我们手动把 NVMe→0、USB→8、EtherCAT→0、默认掩码设管家核，目的就是让中断远离 4-7。但 irqbalance 每 10s 会覆盖重排，可能把中断路由回隔离核，前功尽弃。

mask 非 disabledisable 包更新可能重 enable；mask 软链 /dev/null，任何启动尝试永久拒绝。

f1-rt-disable-thp.service建议服务层禁 THP（双保险）

是什么独立 systemd oneshot，Before=basic.target 早期 echo never 到 enabled 和 defrag。

为什么 GRUB 已设还做部分发行版 init/tuned/cloud-init 会在启动后期重写 always/madvise 覆盖；服务层在它们之前再写 never 堵覆盖路径。defrag 与 THP 是独立开关，需单独写。

启动层 · set_rt_env.sh（8 步，开机经 f1-rt-setup.service 调用）

① governor=performance必须全核固定最高频

是什么scaling_governor 是 cpufreq 给每核选的调频策略。常见 performance（固定最高）/powersave/schedutil（按负载动态）。performance 固定最高频。

为什么即使禁了 intel_pstate，governor 若仍动态档频率会摆动，周期执行时间不一致。

全核管家核也固定，避免后台频率切换产生额外抖动。

② echo 0 > cpufreq/boost必须禁睿频 Turbo Boost

是什么睿频是 Intel CPU 让单核临时超标称最高频的机制。cpufreq/boost 是 ACPI cpufreq 总开关，0 关闭。

为什么禁睿频频率随温度/负载变，同一周期频率波动 → 执行时间波动 → 抖动。固定标称最高频，可预测。

用 boost 非 no_turbo因 intel_pstate=disable，intel_pstate/no_turbo 节点不存在；改用 acpi-cpufreq 的 boost。

③ default_smp_affinity 兜底必须运行时精确兜底新中断默认核

是什么/proc/irq/default_smp_affinity 是"新中断默认落脚 CPU 掩码"，热插拔设备注册时按掩码分配。

与 GRUB 两层GRUB irqaffinity= 早期兜底（见内核层）；此处 systemd 阶段按实际在线 CPU 动态计算，拓扑与预期不符仍能正确排除隔离核。

fallbackpython 失败兜底 fff0f = CPU 0-3 + 8-11。

④ NVMe 队列 → CPU 0必须NVMe 中断移出实时核

是什么NVMe SSD I/O 完成通过多队列中断通知，i7-12800H 上每队列一 MSI-X 中断，默认分散多 CPU。

为什么非 kHz 热路径，但分散到 4-7 污染隔离核。统一迁 CPU 0 让隔离核干净。

⑤ xHCI/r8152 → CPU 8必须·关键修正USB 网卡(含 Livox)中断绑导航核

是什么xHCI 是 USB 3.0 主控驱动，r8152 是 RTL8153 USB 网卡（Livox MID-360 雷达用）驱动。收发中断走 xHCI MSI-X，非独立网卡中断。

为什么 CPU 8Livox 10Hz 数据不大需稳定，CPU 8 导航核不在隔离集、也不和 EtherCAT 抢 CPU 0。

关键修正smp_affinity 按十六进制解析，CPU 8 = bit 8 = 0x100。原 md 写 echo 256（十进制 256 字符串）被内核按十六进制解析成 0x256=598=CPU{1,2,4,6,9}，直接污染隔离核 4/6。已修正为 echo 100（0x100=CPU 8）。

⑥ EtherCAT 网卡 → CPU 0必须EtherCAT 硬中断落管家核

是什么enp2s0（Intel igc 板载）是 EtherCAT 物理载体。SOEM 主站 1kHz 主动轮询，每次收发一帧，网卡硬中断在收发完成时触发。

为什么 CPU 0SOEM 是主动轮询模型，实时性由隔离核 ecat_io_loop 保证，网卡硬中断只需快速应答。落管家核 CPU 0 不抢隔离核，硬中断不进实时核，周期不被打断。

⑦ ethtool 网卡调优建议·保险关省电/聚合，1kHz 收发路径最可预测

逐子项

  • -G rx 128 tx 128 — 设收/发环形队列长 128。太短突发帧丢；128 够覆盖 1kHz 突发。
  • -K gro/gso/tso/lro/rxvlan/txvlan off — 关硬件卸载。gro/gso/tso 把多帧合并大包再交 CPU，合并有延迟；lro 类似且对实时有害；vlan 对 EtherCAT 裸帧无意义。关掉让每帧独立及时交 CPU。
  • -C adaptive-rx/tx off, rx-usecs 0 tx-usecs 0 — 关自适应中断聚合。网卡默认攒帧攒段时间再发中断（省中断数加延迟）。rx-usecs 0=收到帧立即发中断，1kHz 不能等。
  • -A rx/tx off — 关收/发流控（pause frame）。流控让对端"等一下"，对主从同步有害。
  • -A autoneg off（默认关，需现场验证）— 关自动协商强制速率双工。风险：对端未固定速率则链路协商失败、WKC 丢。仅链路已 autoneg on 稳定验证 WKC 后再手动开。
  • ip link set txqueuelen 100 — 发送队列长 100，避免排队延迟。
⑧ swap 兜底必须运行时再确认 swap 已关

是什么见 OS 层 swap 卡。此处开机再 swapon --show 检查一次，若仍激活（fstab 恢复/手动 swapon）则 swapoff -a。双保险。

明确排除 · 不做的项及理由

mce=off排除不关硬件故障上报

为什么不做MCE（Machine Check Exception）是 CPU 硬件故障上报。执行器是安全系统，不应关闭硬件告警——真出硬件问题要能知道。

nosmt排除不砍超线程

为什么不做nosmt 禁用全部超线程。但大脑（导航）需要全部线程算力，砍掉超线程=砍大脑。靠 isolcpus 精确隔离实时核即可，不必全局禁 SMT。

idle=poll排除不让 CPU 空转 100%

为什么不做idle=poll 让隔离核空闲时死循环不进睡眠，延迟最低但热失控（CPU 永远 100% 发热）。F1 用 cstate=0 + performance 已够，不值得冒热风险。

rcu_nocb_poll排除不让管家核常驻轮询

为什么不做它让管家核开 RCU 轮询线程主动拉取回调，延迟更低但常驻一个轮询线程干扰大脑（导航）CFS 调度。大脑也要跑得好，不能为小脑的边际增益牺牲它。

验收一句话

重启后核对

内核：uname -r 含 -realtime；cat /proc/cmdline 含 isolcpus=4,5,6,7 / nohz_full / rcu_nocbs / irqaffinity=0-3,8-19。

OS：全核 scaling_governor=performance；swapon --show 空；sysctl kernel.sched_rt_runtime_us=-1（RT 权限不查 ulimit——控制服务以 root 运行，不受 PAM rtprio/memlock 约束）。

线程：ps -T -p $(pidof aimrt_main) -o tid,comm,cls,rtprio,psr → ecat_io_loop 为 FF:90 在 CPU4，rl_control_pub_thread 为 FF:80 在 CPU6，其余 TS。

延迟：sudo cyclictest -l 100000 -m -Sp90 -p99 -h400 -q，最大延迟 < 100μs（同机负载）。

C3 · ONNX 线程限制待实现rl_controller.cc · 加 SetIntraOpNumThreads

现状rl_controller.cc LoadModel() 只设了 SetInterOpNumThreads(1)（算子间串行），但未设 SetIntraOpNumThreads，ONNX Runtime 默认用全部 CPU 核心（i7-12800H = 20 线程）做算子内并行。

影响RL 模型很小（47/53 维输入，12/14 维输出），20 线程并行开销远超收益，反而引入调度抖动。

方案YAML 的 onnx_conf 加 intra_op_threads: 1 字段，默认 1（单线程），以后想调不用改代码。LoadModel() 读取并调用 SetIntraOpNumThreads()。

应用层 preflight待实现run_main.sh --check-only · 启动前 7 项检查

来源f1_realtime_optimization.md §4.1

7 项检查（原 8 项含 ulimit -r，因控制服务改以 root 运行、rtprio/memlock limits 取消而删去）

  • PREEMPT_RT 内核 — /sys/kernel/realtime == 1，否则拒绝启动
  • swap 关闭 — swapon --show 为空，否则拒绝启动
  • governor = performance — 全核检查，否则拒绝启动
  • 配置文件存在且可解析 — x1_cfg.yaml 及其引用的 rl_x1.yaml、dcu_x1.yaml、joy_x1.yaml 全部存在且 YAML 解析成功，否则拒绝启动
  • EtherCAT 网口存在且 UP — 从配置解析 ifname 后检查，否则拒绝启动
  • bind_cpu 合法 — 配置的 CPU 号在线，否则拒绝启动
  • ONNX 模型文件存在 — 从 rl_x1.yaml 解析路径，否则拒绝启动

关于"配置文件存在且可解析"这里指的是 install/linux/bin/cfg/x1_cfg.yaml——它是 aimrt_main 的主配置，声明了加载哪些模块、每个模块的 cfg_file_path 指向哪里、executor/channel/log 怎么配。preflight 会递归验证它引用的 3 个子配置（rl_x1.yaml / dcu_x1.yaml / joy_x1.yaml）也都在且可解析。目的：fail fast——在 aimrt_main 启动前就发现配置缺失/损坏，而非跑一半崩溃。

验证脚本完善待实现verify-rt-config-claude-merge.sh · 补覆盖

现状verify-rt-config-claude-merge.sh 是只读验证脚本，覆盖内核层（GRUB 参数）、OS 层（governor/boost/THP/swap/sysctl/irqbalance）、IRQ 亲和性（NVMe→0、xHCI→8、EtherCAT→0）、ethtool 调优、systemd/udev。

待补与 f1-rt-config-claude-merge.sh（配置写入脚本）的 preflight() 形成三层验证体系：

  • 层 1 — 配置脚本自身 preflight（root/OS/VM/依赖）
  • 层 2 — 独立验证脚本（系统级只读检查）
  • 层 3 — 应用层 preflight（YAML/模型/网络，run_main.sh --check-only）

判断三层各司其职，不应合并。层 1 是"写入前自检"，层 2 是"写入后验证"，层 3 是"每次启动前守护"。
