01 · 总纲

PREEMPT_RT 实时内核

一句话：调度员能不能随时插话。普通内核要等手头这封信写到一句末尾才能接急件，RT 内核随时能插。

普通内核急件来了也得等
RT 内核急件随时插队

把 CPU 想成一个只会写信的调度员。机器人每 1 毫秒就要收发一次 EtherCAT 数据——这是特级急件。普通内核像礼貌的办事员："等我这句话写完再接你"，急件可能被压几十微秒。RT 内核把"句子"切得很碎，PREEMPT_RT 让急件随时能插队，1ms 的活才准时开干。

普通内核唤醒后执行延迟抖动大，1kHz 循环尾部不可控
RT 内核所有后续优化的前提，uname -r 含 -realtime

02 · 内核层

isolcpus + HT sibling — 划专用车间

一句话：把 4 个 CPU 划成"只许实时工人进"的专用车间，还得连超线程兄弟一起圈走。

没隔离谁都能挤进 4/6 号
isolcpus=4,5,6,7整个物理核圈走

CPU 是个有 20 个工位的工厂。isolcpus=4,5,6,7 就是把 4、5、6、7 号工位用隔离带围起来，只有 EtherCAT 和 Control 两个特级工人能进，ROS、DDS、日志这些普通工人只能去剩下的 16 个工位。

为什么是 4,5,6,7 而不是只 4,6？ 因为 4 和 5 是同一个物理车间里的两个工位（超线程 Hyper-Threading），它们共用一个工具柜（L1/L2 缓存）。只圈 4 号、放任 5 号，普通工人挤进 5 号就会和实时工人抢工具柜——所以必须把整个物理车间连兄弟一起圈走。

没隔离普通线程被调度到实时核，缓存被驱逐，1kHz 出现延迟尖峰
隔离 4,5,6,7实时核缓存独占，周期可预测

03 · 内核层

nohz_full 关掉车间的打卡铃

一句话：别再每 4 毫秒响一次铃打断实时工人。

铃照响每 tick 打断一次
nohz_full铃关了，连续干活

即使隔离了车间，内核仍会每秒发 HZ 次"打卡铃"（tick，默认 250 次/秒 ≈ 每 4ms 一次）给每个核。铃一响，实时工人得停下手里 1ms 的精细活、抬头看钟、重新排队。对 1ms 周期来说，一次铃响就是数十微秒抖动。nohz_full = 把实时车间的打卡铃关掉：车间里只剩这一个工人在干活时，不需要周期性点名，让他连续顺滑地干。

铃照响每 4ms 一次 tick 中断，数十微秒抖动
nohz_full关周期 tick，需配合 rcu_nocbs 才真生效

04 · 内核层

rcu_nocbs 派清洁工收垃圾

一句话：别让实时工人自己倒垃圾，派管家核的清洁工来收。

自己倒垃圾偶尔停下手
rcu_nocbs清洁工溜进来收走

工人干活会产"垃圾"——内核叫 RCU 回调（一种延迟清理工作）。普通情况垃圾堆在各自车间，实时工人偶尔得停下手里活去倒一趟，就是不可预测的微秒抖动。rcu_nocbs = 派管家核的清洁工定期溜进实时车间把垃圾袋拎走，实时工人永远不用自己中断。

不迁RCU 回调命中实时核关键路径，微秒抖动
rcu_nocbs回调迁到管家核执行，实时核清净

网卡像快递员，每来一个包裹就敲门（中断 IRQ）。敲哪个车间的门，那个工人就得停下手头活去签收。irqaffinity=（GRUB 最早期）和 smp_affinity（运行时）就是规定快递员只能敲指定门。

绑管家核EtherCAT→CPU0，USB/Livox→CPU8，实时核清净

governor=performance + cstate=0 别变速、别睡沉

一句话：跑步机钉死最高档，午觉只许打浅盹。

intel_pstate + 深睡忽快忽慢
Z
z
z

两层合一：
① 频率：CPU 频率像工人跑步速度。intel_pstate 是"智能跑步机"，按忙不忙自动调速度——每个 1ms 周期跑的速度不一样，完成时间就长短不齐。governor=performance 把跑步机钉死最高档，每个周期一致。

动态调频 + 深睡频率波动 + 唤醒延迟，周期执行时间不稳

07 · OS 层 + 代码层

memlock + swap off 把工具钉在工位上

一句话：别让管家把实时工人的工具搬去仓库，直接把仓库也封了。

swap 开 + 没锁工具被搬走
mlockall + swapoff钉住不动

工人的工具放在工位上（内存）。内存一紧，管家会把不常用的工具搬到远处的仓库（swap，写磁盘）。实时工人正要用某工具，发现被搬走了，得跑去仓库取——毫秒级缺页中断，1ms 周期直接报废。控制服务以 root 运行，mlockall() 在 root 下不受 memlock 限制，直接用钉子把工具钉死在工位，谁也不许搬；swapoff 干脆把仓库封了，连搬的机会都没有。（memlock limits 已取消——非 root 才需配额，本项目不涉及）

swap 开 + 没锁内存页被换出，缺页延迟达毫秒级
mlockall + swapoff内存页常驻物理内存，零换出

08 · OS 层

SCHED_FIFO（root 免 rtprio） 金卡随时插队

一句话：给实时线程发金卡，随时插到普通队最前面。

代码 <0 bug金卡申请被吞
root 免 rtprio金卡直接插最前

普通线程排资历队（SCHED_OTHER，轮流上）。实时线程要拿金卡（SCHED_FIFO，随时插队最前面，90 分的比 80 分的更优先）。控制服务以 root 运行，root 设 SCHED_FIFO 不受 rtprio 限制——金卡直接发，不需 PAM 授权（非 root 才需 rtprio 配额，本项目不涉及）。真正的风险在代码层：pthread_setschedparam 返回值检查写成 <0（永不触发），就算金卡没发成，失败也被静默吞掉，程序以为拿到了 RT 其实根本没拿到，还毫无察觉。

本项目：EtherCAT 线程金卡 90 分、Control 线程金卡 80 分，root 下都直接发；代码层已修复为 != 0 检查（C1）才是金卡真生效的前提。

代码 <0 bugRT 调度静默失败，程序自以为实时其实没拿到
root + FIFO实时线程随时插队；代码 != 0 检查才真生效（rtprio limits 已取消）

09 · OS 层 + 启动层

THP=never 别中途整理书架

一句话：别在干活时突然停下来重新整理书架。

THP 自动合并中途整理
THP=never书架保持原样

内存像书架，普通每本书占一格。透明大页（THP）会自动把相邻几格合并成大书架，一次放更多——听着挺好。但合并/整理（defrag）的过程要停下现有活去重新摆放，对实时线程就是不可预测的抖动。transparent_hugepage=never = 不自动整理，书架保持原样，实时工人不被中途打断。（GRUB + systemd oneshot 双保险，开机最早期就关掉。）

THP 自动后台合并/碎片整理打断实时线程
THP=never不自动整理，内存布局稳定

10 · 内核层 · 杂项

tsc / watchdog_thresh / audit 调低看门狗、关掉多余巡逻

一句话：统一对一块秒表，把巡检从每秒一次拉到每分钟一次。

默认多个巡逻 + 多块表
关巡逻 + 一块表清静

剩下几个小项都是拉长巡检间隔：
• tsc=reliable + clocksource=tsc：让所有核看同一块 CPU 内置秒表（TSC）对时，别各看各的（不同时钟源会漂移），并信任它够准不用反复校。
• watchdog_thresh=60：调低硬锁死看门狗巡逻频率——从 10 秒一次拉到 60 秒一次（NMI 从每秒一次降到每分钟一次），保留卡死诊断能力但把干扰降到几乎为零。
• audit=0：关审计日志的周期性记录。
都是减少周期性打扰实时核的巡检。

默认开看门狗/审计周期性打扰，时钟源漂移
调低看门狗 + 统一 TSCNMI 每分钟一次几乎无干扰，保留卡死诊断；时间基准一致

11 · OS 层 · sysctl

sched_rt_runtime_us=-1 解除"强制让出"

一句话：别每秒强制把实时工人踢出去 50 毫秒。

默认 950000每秒让出 50ms
强制让出 50ms
=-1 解除隔离核 100% 给 RT

内核默认有张"安全网"：RT 线程每 1 秒最多连续跑 950ms，剩下 50ms 强制让给普通线程（防 RT 独占把系统锁死）。但在隔离核上——这核本来就只跑 RT——这个强制让出纯属多余，反而每秒扫过一次撞上实时周期，制造抖动。sched_rt_runtime_us=-1 = 在隔离核上解除这道限制，RT 可 100% 连续占用。

默认节流每秒 50ms 让出窗口撞实时周期
=-1隔离核 100% 给 RT，无强制让出

12 · OS 层 · sysctl

timer_migration / numa_balancing / stat_interval 关掉跨核游走

一句话：撤掉几个会"跨核搬、远程唤、周期统"的小动作。

默认到处游走唤信
全关/拉长就地静止

三个"零开销保险"，关掉减少跨核干扰：
• timer_migration=0：定时器默认会在忙/闲核间搬家找最闲的跑，对隔离核是潜在干扰，关掉让它就地跑。
• numa_balancing=0：NUMA 内存自动均衡会跨节点搬内存页。本机单 NUMA 节点，这功能纯多余且触发远程访问，关掉。
• vm.stat_interval=10：vmstat 默认每秒统计内存状态并唤醒一次，拉长到 10 秒，减少周期性唤醒。

延伸澄清 · 三个易混点

① nohz_full 和 timer_migration=0 重复吗？不重复。 一个挡"周期检查"、一个挡"外来任务"，叠加才真清净——两者都是零开销保险，建议都关：
机制 挡的打扰 原理
nohz_full 周期性时钟 tick 关掉隔离核例行的"点到"中断本身（需 rcu_nocbs 配合、且核上只剩目标线程才生效）
timer_migration=0 定时器搬家 别核的定时器别搬来隔离核执行

② NUMA 内存是什么，怎么查单不单
NUMA = 非一致性内存访问：多 socket 服务器每个 CPU 插座有自己的"本地内存"，跨插座访问慢。内核的 numa_balancing 会周期性扫描进程内存页、搬到"正在跑它的 CPU 的本地节点"以提速。本机 i7-12800H 是单 socket 单 die，只有一个 NUMA 节点，这功能纯多余，且其扫描+搬页的周期动作本身就是对实时核的干扰，故关掉。
查本机单不单：numactl --hardware / lscpu | grep NUMA / ls /sys/devices/system/node/，只列 1 个节点就是单。

③ vmstat 统计到底统计啥
内核维护一组内存计数器（空闲/缓存/swap 用量/换页率/中断率…），供 vmstat 命令、监控工具、OOM killer 查阅。它 per-CPU 统计，默认每秒唤醒一次把各核数字聚合刷新到全局——这每秒一次的唤醒对隔离核是噪声。vm.stat_interval=10 把刷新间隔拉到 10 秒，频率降 10 倍，统计仍然准确，只是不再"秒级刷新"——对实时调度反而更干净。
默认定时器/NUMA/vmstat 周期游走与唤醒
关掉/拉长就地运行，减少跨核干扰

NVMe 队列中断 高速传送带的卸货工

一句话：固态盘的卸货工别站到实时车间门口，全去管家门口卸。

0

先说 NVMe 是什么：它是直接插在 PCIe 总线上的固态盘，不像机械盘要经过 SATA 控制器和盘片旋转，读写极快。它靠"多队列"并行卸货——每个队列一个 MSI-X 中断，像传送带上一排卸货口。默认这些卸货工（队列中断）随便站，可能站到实时车间门口堵路。echo 1 > /proc/irq/<nvme>/smp_affinity = 让所有 NVMe 卸货工全站到 0 号管家门口。

15 · OS 层

cpufreq/boost=0 锁死"爆发档"

一句话：跑步机最高档之上那个会自动飙的爆发档，关掉。

Turbo 开偶发飙高不稳
爆发档↑
boost=0锁死稳定最高频

CPU 标称最高频之外还有个"爆发档"（Intel Turbo Boost）——看着闲就自动临时飙到比标称更高的频率。听着像好事，对实时却是坑：能飙多久、飙多高随温度/核数/功耗动态变，每个 1ms 周期实际跑的频率不一，执行时间就不齐。因 intel_pstate=disable 后 no_turbo 节点不存在，走通用路径 /sys/devices/system/cpu/cpufreq/boost 写 0，把爆发档也锁死，只认稳定最高标称档。

和卡 06 的关系：06 是"固定到最高档"（governor=performance），15 是"连爆发档也别用"（boost=0）——两层一起，频率才真稳。

Turbo 开频率偶发飙高，周期执行时间不稳
boost=0锁死稳定最高频，每个周期一致

16 · OS 层

ethtool 给网卡门口立规矩

一句话：别攒车、别让网卡帮忙打包、把收件筐加大。

子 A · 中断聚合 rx-usecs 0：攒车敲门 vs 一来就敲
rx-usecs 默认攒一车才敲
rx-usecs 0一来就敲
子 B · 硬件卸载 -K gro/gso/tso off：网卡打包 vs CPU 直接掌控
卸载开网卡帮忙打包
卸载关CPU 直接掌控小包

网卡是 EtherCAT 数据进出的门口，ethtool 给它立几条规矩：
• 中断聚合 rx-usecs 0：默认网卡"攒一批包、攒够时间再发一次中断"（少打扰 CPU），但实时要每个包立即通知——设 0 = 一来就敲。
• 硬件卸载 gro/gso/tso/lro off：网卡硬件帮忙把小包合并成大包/拆大包（省带宽），但对实时收发是额外且不确定的处理延迟，关掉让 CPU 直接掌控原始小包。
• ring buffer -G rx/tx 128：网卡收件筐加大，瞬时 burst 不丢包。
• 流控 -A rx/tx off：关暂停帧，别让对端喊"我忙"网卡就停发。
• txqueuelen 100：发送队列长度。

延伸澄清 · 两个追问

① 关了卸载"不攒包"，ring buffer 和 txqueuelen 还有必要吗？有，不是一回事。 "攒"在这卡里其实是两个不同维度：
• 硬件卸载（GRO/GSO/TSO/LRO）是协议层把小包合并成大包/拆大包的"加工服务"，省 CPU 省 带宽。关掉 = 不做这种内容重组，包原样进出——关的是"包的加工"，不是"包的暂存"。
• ring buffer（-G rx/tx 128）是网卡硬件里的 DMA 暂存筐，防 CPU 来不及取包时丢包；txqueuelen（100）是内核 qdisc 软件排队等发的队伍长度。这俩是"暂存"，和"合并"正交。
反而不合并后，原来一个合并大包能装的量变成几十个小包一个个过，在途小包数反而更多，暂存筐更要够大，否则 CPU 慢一拍就丢——所以 ring buffer 128 在关卸载后更有意义，不是更没必要。txqueuelen 默认 1000 太长会堆积延迟，100 是"队伍短不积压"与"别太短丢包"的折中；EtherCAT 是 1kHz 小帧轮询、流量小而稳，100 绰绰有余且不会满。

② "对端忙不忙"指的是谁？就是 EtherCAT 从站。 EtherCAT 链路：本机主站网卡（enp2s0）──网线──网线另一头第一个从站网口，"对端"就是那个从站。PAUSE 帧是 IEEE 802.3x 流控：对端（从站）buffer 快满了就发个 PAUSE 喊"别发了"，本端网卡收到就停发一段时间。问题是 EtherCAT 是主站主动周期轮询——主站每周期发一帧、从站转发并回填数据，从站 buffer 极少满、几乎不会喊停。但"万一被暂停"那一下，主站 TX 时序就乱了、那周期 WKC 就错。关流控 = 宁可让万一的拥塞以"丢包→WKC 异常可检测"的形式暴露，也不要"被暂停→时序错乱→不可见"。所以 rx/tx 都关。
默认攒包/帮忙打包，延迟不定且可能丢
rx-usecs 0 + 卸载关 + 筐加大即时掌控、CPU 直收、不丢

17 · 刻意不做

有些"优化"代价太大 — 刻意不做

一句话：这几个听着像优化，但执行器/大脑扛不住，故意的。

idle=pollCPU 100% 空转发热
▲▲
不用 idle=poll温度正常

别处教程会推荐这几个，这里刻意不做：
• idle=poll 不用：让隔离核不睡觉、空转轮询等活，延迟确实最低。但 CPU 100% 满载持续发热（热失控），小主机散热扛不住会触发降频保护，反而更糟。
• nosmt 不砍：砍掉超线程能消除 sibling 干扰，但本机大脑(导航)的 ONNX 推理需要超线程算力，砍了大脑变慢。所以选"隔离 sibling"而非"砍 SMT"。
• mce=off 不关：MCE 是硬件故障上报（内存 ECC 错、CPU 错）。执行器安全系统不能蒙眼跑——出了硬件故障你得知道，宁可抖动也要告警。
• rcu_nocb_poll 不开：让管家核不睡觉专职轮询等 RCU，对实时核是好事，但管家核也是大脑核，常驻轮询会干扰大脑推理。所以选 rcu_nocbs（迁移）而非 rcu_nocb_poll（常驻）。

盲目开热失控/砍算力/丢硬件告警/扰大脑
刻意不做保执行器安全与大脑算力

看上面接力，"攒"在收发路径里其实是三种不同性质的暂存/加工，别混成一谈：

三种"攒" · 一张表分清
机制 是哪种"攒" 关掉/不当会怎样
ring buffer -G rx/tx 128 硬件 DMA 暂存筐（防丢） 筐小→CPU 慢一拍就丢包
rx-usecs 中断聚合 攒车才敲门（省 CPU 中断） 敲门晚→包延迟到，设 0 即时敲
GRO/GSO/TSO/LRO 硬件卸载 协议层合并/拆分加工（省带宽） 加工有不确定延迟→关掉，包原样进出
txqueuelen 100 内核 qdisc 排队等发（队伍长度） 默认 1000 太长→堆积延迟，100 折中不积压
所以"关了卸载不攒包，ring buffer / txqueuelen 还有必要吗？"——有必要，而且更有必要。 卸载关掉的是"包的内容加工"（合并/拆分），不是"包的暂存"。反而不合并后，原来一个合并大包的量变成几十个小包一个个在途，在途小包数更多，暂存筐（ring buffer）和排队队伍（txqueuelen）更要够大、更要短，否则 CPU 慢一拍就丢、队伍一长就延迟。两者和"合并"是正交的维度。

关于流控："主站发包不能被从站牵着鼻子走"。 发包路径末端 TX 筐 → 网线 → 对端（EtherCAT 从站）。PAUSE 帧（IEEE 802.3x）是对端 buffer 快满时喊"别发了"、本端网卡收到就暂停 TX。但 EtherCAT 是主站主动周期轮询——主站每周期发一帧、从站转发回填，从站 buffer 极少满、几乎不喊停。可"万一被暂停"那一下，主站 TX 时序就乱、那周期 WKC 就错。关流控 -A rx/tx off = 宁可让拥塞以"丢包→WKC 异常可检测"暴露，也不要"被暂停→时序错乱→不可见"。主站的发包节奏由主站自己的 1kHz 周期定，不能交由从站的 buffer 状态来 gate。
默认筐小丢包/攒车延迟/合并加工不定/队列堆积/可能被从站暂停
筐大+即时+关卸载+短队+关流控CPU 直收原包、不丢、不被牵制

19 · 串联

开机全流程串联 — 一个脚本跑一次，往后每次开机自动上膛

前 18 张卡讲的是每个零件长啥样；这张讲零件怎么装上机器、机器开机时按什么顺序自动把它们用起来。两个时间：① 部署（跑一次）② 开机（每次重放）。

① 部署 · 跑一次主脚本（离线、一次性总装，跑完就退场）

step 0 · preflight 自检：root / 非虚拟机 / 20 线程 / 装好 python3 ethtool 不落文件 · 只挡住错误环境
step 1 · 检测 / 装 RT 内核 已是 -realtime 内核就跳过；没装则经 Ubuntu Pro 装（支持 token 非交互） 不落文件 · 重启进 RT 内核后后续才真正生效
step 2 · 写 3 个 drop-in 配置 99-f1-rt.cfg（12 内核参数）· 99-f1-rt.conf（RT 节流解除 / 定时器静音 / NUMA 关自平衡 / vmstat 减唤醒） 99-f1-rt.cfg → /etc/default/grub.d/（GRUB 扫它，拼进内核启动命令行）· 99-f1-rt.conf → /etc/sysctl.d/（sysctl 扫它，设内核运行参数）
step 3 · 写 2 服务 + 1 脚本 + 1 规则 f1-rt-disable-thp.service（早期禁大页）· set_rt_env.sh（唯一真脚本，0755）· f1-rt-setup.service（开机拉脚本）· governor.rules（udev 兜底） thp.service + setup.service → /etc/systemd/system/（装两个）· set_rt_env.sh → /opt/f1/scripts/run/ · governor.rules → /etc/udev/rules.d/
step 4 · 运行时动作 swapoff -a + 注释 fstab swap · 停用并 mask irqbalance 改 /etc/fstab · mask irqbalance.service（不是落新文件，是改状态）
step 5 · update-grub + 退出 把 12 内核参数刷进引导 · 打印 summary · 脚本退场 此后每次开机，系统自己读那些文件，不再需要本脚本

② 开机 · 每次自动重放（系统按固定时序读那些文件，无需人工）

电源 → BIOS → GRUB GRUB 读 99-f1-rt.cfg → 装上 12 个内核参数（PREEMPT_RT / 隔离 4-7 / 关 tick / RCU 搬走 / 关睿频 / tsc）= 内核实时能力 读它的：引导器 · 生效时机：内核起来的一瞬间，早于一切服务
内核启动 sysctl 读 99-f1-rt.conf → RT 不节流 / 定时器不跨核游走 / NUMA 不自平衡 / vmstat 减唤醒 读它的：systemd-sysctl（开机自动）· 与 GRUB 同属"持久配置"
systemd sysinit（最早） f1-rt-disable-thp.service oneshot → 禁透明大页（在 basic.target 之前生效，越早越好） 读它的：systemd · 与 GRUB 的 transparent_hugepage=never 互为双保险
systemd multi-user f1-rt-setup.service 拉起 set_rt_env.sh → 恢复运行时状态（重启会丢的那些）：governor=performance · 关睿频 · IRQ 兜底 · NVMe→CPU0 · USB→CPU8 · EtherCAT→CPU0 · 网卡 ethtool（筐 128 / 关聚合 / 关卸载 / 队 100）· swap 兜底 闹钟（service）每天启动机器人（set_rt_env.sh）拉窗帘 —— 见下文比喻
控制服务启动（root） 控制服务以 root（sudo）启动，pthread_setschedparam/mlockall 在 root 下不受 PAM rtprio/memlock 限制——无需登录会话配额（f1-realtime.conf 已取消，不建 f1rt 组） 真正前提：代码层 pthread_setschedparam 返回值检查 != 0（C1 修复），失败即日志告警而非静默吞掉
udev 事件（cpu add） 99-performance-governor.rules → 任何 CPU 上线即写 performance（补 set_rt_env.sh 管不到的时段：开机后才上线的 CPU，仅兜 governor 这一项，不兜整个脚本） 读它的：udev（设备事件）· 防热插拔 / 省电策略把 governor 改回去
手动起跑 motion-control 人敲 install/linux/bin/run.sh（setcap cap_net_raw + aimrt_main）→ 程序内部 pthread 建两条 1kHz 线程并绑核 / 设优先级：ecat_io_loop（CPU4, FIFO90）+ rl_control_pub_thread（CPU6, FIFO80）。脚本不自动拉程序—— f1-rt-setup.service 里的 Before=f1-motion-control.service 是占位钩子（该 service 未生成），现阶段保持手动启动 启动入口 run.sh · 脚本只管环境不管程序 · 能力此时真正"落到"目标线程，前面所有环节都是为这一刻 · 想全自动再补一个 service 即可

看上面两段轴：部署是"一次性交房"，开机是"每天自动复位"。一个比喻串起来：

装修总包 + 拉窗帘机器人 + 闹钟

主脚本像装修队总包，跑一次把硬装做完：固定设施装好（3 个 drop-in 配置 = 持久装修，摆那儿系统自己读），再留下对付"每天要做的"三样东西——
① 每天拉窗帘的机器人 = set_rt_env.sh（恢复重启会丢的运行时状态：governor、IRQ、网卡参数）
② 每天到点启动机器人的闹钟 = f1-rt-setup.service（每次开机把它拉起来）
③ 设备插拔兜底 = governor.rules（udev 事件再补一刀）

机器人必须是独立文件——闹钟（systemd service）只能指向磁盘上一个路径去执行，没法指向"总包里的一段代码"；总包跑完就退场，不会每次开机重来。

为什么不能全塞进主脚本一个文件？ 主脚本是一次性工具，跑完就退出，不能每次开机重跑；持久配置用 drop-in 机制（删文件即撤销）最稳最可回滚；运行时命令必须独立成脚本让 systemd 指向它、每次开机调用；独立成文件还方便人工随时 sudo set_rt_env.sh 重跑验证（幂等）。
