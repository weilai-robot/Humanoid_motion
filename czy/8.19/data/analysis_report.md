## 二、逐文件详细结论

### ① walk_diag_20260819_150724 — LT 刹车测试 ✅

**指令曲线**: 0.4 m/s 恒速 6.2s → LT 刹车（`(1-t/8)²` 二次凹减速，8s 归零）→ 14s 后小幅加回 0.12 m/s。

**关键指标**:
- 自适应周期: 0.4 m/s 时 `cycle_time=0.583s`（理论 0.583s，**零偏差**），减速中平滑收缩至 0.35
- 姿态: roll ±5.6°、pitch ±3.7°，**全程无越限**
- 右膝跟踪误差: 均值 0.206 rad、峰值 0.815 rad
- 踝力矩: ±20 Nm（温和）
- 相位冻结 568/1870 帧（含低速段和站立段，符合预期）

**结论**: **8 秒慢减速是安全的**。EMA 与指令曲线基本重合（慢速变化下滞后可忽略），cycle_time 收缩平缓，步态稳定过渡到站立。yaw 净漂 +44.4°（无闭环，直线度差是唯一问题）。

### ② walk_diag_20260819_150956 — 满速恒走 ✅

**指令曲线**: 0.6 m/s 恒速 4.4s。

**关键指标**:
- `cycle_time=0.700s`（满速最长周期，符合映射）
- 姿态: roll ±5.0°、pitch ±3.0°
- 右膝跟踪误差: 峰值 0.621 rad；踝力矩 ±26 Nm
- 无相位冻结帧（全程行走）

**结论**: **满速恒走没问题**，验证了速度-周期映射上边界（0.6 m/s ↔ 0.7s）的正确性。

### ③ walk_diag_20260819_151452 — 快速减速摔倒 ❌

**指令曲线**: 1.6s 斜坡加速 0→0.6 → 保持 1.8s → **约 1s 快速减到 0**。

**失稳过程时间线**:
| t | 事件 |
|---|------|
| 0~1.6s | 斜坡加速至 0.6，姿态平稳（roll <4°） |
| 3.4s | 开始快速减速，cmd 从 0.6 直落 |
| 5.4s | **pitch 首破 10°**，此时 cmd=0.03、EMA=0.20（滞后 +0.17）、cycle=0.47 快速收缩中 |
| 5.4~5.9s | pitch 爬升至 +19.8°，yaw 以 ~200°/s 旋转（-34.9°→+151.7°），左踝力矩 ±48 Nm 挣扎 |
| 5.9s | yaw 冻结在 151.4°（**倒地确认**），此后踝力矩冲到 +121 Nm |
| 10.6s 后 | 有人以 0~0.125 小幅推杆，指令反复穿越 0.05 阈值 → 相位反复冻结/解冻 → 步-停抖动（975/2000 帧冻结） |

**结论**: 失稳点在减速斜坡中段——指令已接近 0 但 EMA 仍拖着 0.2 m/s、周期正以最大速率收缩、相位即将被冻结。三重扰动叠加。

### ④ walk_diag_20260819_151632 — 三角波 ✅（有瑕疵）

**指令曲线**: 三角波 0→0.525→0（各 2.5s，斜率约 0.21 m/s²）→ 之后 0~0.125 小幅往复。

**关键指标**:
- 峰值 `cycle_time=0.570s`（对应 0.525 m/s，符合映射）
- 姿态: 仅 11 帧瞬时 pitch 11.9°（无持续失稳）
- 站立冻结 1774/2000 帧——大部分时间在站立

**结论**: **中速三角波（0.21 m/s² 变化率）安全**。有效数据里真正行走的只有 2.3s，后半段小幅推杆全在 0.05 阈值附近抖动（相位冻结/解冻反复），这段数据对行走评估无贡献，但也侧面暴露了阈值无滞回的问题。

### ⑤ walk_diag_20260819_151821 — 慢加速后快速减速摔倒 ❌

**指令曲线**: 6.1s 缓慢加速 0→0.6 → 6.2s 开始减速（先匀斜率后加速收尾）。

**失稳过程时间线**:
| t | 事件 |
|---|------|
| 0~6.1s | 缓慢爬升到 0.6，全程稳定（roll ±4°）——**慢加速安全再次确认** |
| 6.2s | 开始减速 |
| 6.7s | **失稳**：cmd=0.33、EMA=0.49（滞后 +0.16）、cycle=0.64，roll 首破 -10° |

**结论**: 与 ③ 完全同模式。注意 ⑤ 的减速斜率其实不算极端，但减速进行到一半（cmd 还剩 0.33）时就已经失稳——**不一定要减到 0，减速过程本身就是风险**。

## 三、失稳根因分析

### 失稳模式聚类

| 减速方式 | 变化率 | 结果 |
|---|---|---|
| LT 二次减速 | 峰值 ~0.1 m/s²（渐减） | ✅ ① |
| 三角波对称减速 | ~0.21 m/s² | ✅ ④ |
| 快速斜坡减速 | ~0.5-0.6 m/s² | ❌ ③ ⑤ |

**分界线大约在 0.2~0.5 m/s² 之间。**

### 根因（按可能性排序）

**1. 减速段"步频反向加速"（主要嫌疑）**

EMA（τ=0.5s）滞后使快速减速时出现三重扰动叠加：

```
cmd 已接近 0 ──(EMA 滞后 +0.17)──> 平滑速度仍 ~0.2
                                      │
cycle_time 从 0.7 → 0.35 收缩 ──> 步频 1.43Hz → 2.86Hz（翻倍）
                                      │
cmd ≤ 0.05 瞬间 ──> 相位冻结，摆动腿停在半空
```

机器人在重心尚有前向动能、最需要稳定支撑的时刻，步态节奏被反向加快、然后突然"急停"。训练环境指令 10s 才重采样一次，**从未覆盖这种 1s 内 0.6→0 的快速斜坡分布**——属于 sim-to-real 的指令分布外（OOD）问题。

**2. 真机 kp/kd 与训练配置不匹配（放大器）**

| 关节 | 训练 | 真机 | 偏差 |
|---|---|---|---|
| ankle_pitch/roll kd | 0.5 | 1.5 | **3 倍** |
| knee_pitch kd | 10 | 8 | -20% |
| ankle_roll kp | 35 | 30 | -14% |

踝关节走纯力矩模式（`paralle_list`），kd 过大导致阻尼特性与训练动力学不一致，减速期的姿态扰动被放大。训练时增益域随机化仅 ±20%（0.8~1.2 倍），3 倍偏差已出训练分布。

**3. 站立阈值无滞回（次要，③ 后半段可见）**

指令在 0.05 附近反复穿越 → 相位反复冻结/解冻 → 步-停-步抖动。虽不是摔倒主因，但恶化了低速段的姿态控制。

### 佐证数据

- 两次失稳时 EMA 滞后分别为 +0.17、+0.16 m/s——高度一致
- 失稳时刻 cycle_time 分别为 0.47（收缩中）、0.64（收缩中）——都处于快速收缩段
- 慢减速（①④）EMA 滞后 <0.03 m/s，无失稳

## 四、改进建议（按优先级）

### P0 — 立即执行（不改代码的操作规范）

1. **禁止快速减速**：操作手柄/测试脚本时减速变化率控制在 **≤0.1 m/s²**（0.6→0 至少 6s）。LT 刹车曲线已被验证安全，继续使用。

### P1 — 部署侧代码加固（rl_controller.cc）

2. **指令变化率限幅**：在 `ComputeObservation` 的 cmd 处理处增加斜率限制（如 0.1 m/s per 100ms 帧间限幅），从源头杜绝 OOD 指令进入策略。
3. **cycle_time 收缩限速**：限制周期变化率（如 ≤0.1s/s），避免减速瞬间步频翻倍。
4. **站立判定加滞回**：进入站立 `norm<0.05`，退出需 `norm>0.10`，消除相位抖动。
5. **对齐真机 kp/kd 到训练值**：ankle kd 1.5→0.5、knee kd 8→10、ankle_roll kp 30→35，然后复测快速减速（验证根因 2）。

### P2 — 训练侧（czy/diff）

6. **指令课程中加入快速变速**：resampling 时以一定概率插入 0.5~1 m/s² 的斜坡段，让策略学会应对快速减速。
7. 可选：cycle_time_min 适当调大（如 0.4s），降低静止附近的步频极限，给相位冻结留缓冲。

### P3 — 其他

8. yaw 漂移（① +44°）需处理：恒速直行建议启用 RT 偏航闭环（`rt_walk_verify.py` 的逻辑），或将闭环下沉到 control_module。
9. 诊断日志建议增加"cmd 原始值 vs 限幅后值"区分列，便于后续排查指令源问题。
